# Hardware Script Level 5: Syntactic Sugar (Rule Compilation)

**Version**: 0.1 (Research Phase)  
**Purpose**: High-level rule syntax compilation to physical circuits  
**Status**: 📋 Planned

---

## Overview

Level 5 is the top layer—the user-facing syntax that makes hardware design feel like software development. This layer compiles declarative rules into the physical circuits defined in Levels 0-4.

**Key Principle**: The `rule` syntax is syntactic sugar. It compiles down through all layers to actual transistors, resistors, and copper traces.

---

## Rule Syntax Structure

### Basic Rule

```hw
rule "RuleName":
    if <condition>:
        <action>
    else:
        <action>
```

### Compilation Target

Every rule compiles to:
1. **Sensor Input** → Analog voltage (Level 2)
2. **Comparator Circuit** → Transistor arrangement (Level 3)
3. **Logic Gates** → Standard macros (Level 4)
4. **Output Driver** → Transistor switch (Level 3)
5. **Physical Routing** → Copper traces (Level 0)

## Example 1: Simple Threshold

### User Code

```hw
rule "Night Light":
    if Eye.light_level < 50%:
        LED state is ON
    else:
        LED state is OFF
```

### Compilation Process

**Step 1: Parse Condition**
- Sensor: `Eye.light_level`
- Operator: `<`
- Threshold: `50%` (2.5V if sensor outputs 0-5V)

**Step 2: Generate Comparator Circuit**

```hw
# Internal circuit generated by compiler
add Resistor (10k) named R_div1
add Resistor (10k) named R_div2
add Transistor_NPN named T_comp
add Resistor (10k) named R_pull

# Voltage divider for 50% threshold (2.5V)
connect VCC to R_div1.in
connect R_div1.out to R_div2.in
connect R_div2.out to GND
# Midpoint = 2.5V

# Comparator
connect Eye.output to T_comp.Base
connect VCC to R_pull.in
connect R_pull.out to T_comp.Collector
connect T_comp.Emitter to GND
```

**Step 3: Generate Output Driver**

```hw
add Transistor_NPN named T_output
add Resistor (220) named R_led

connect T_comp.Collector to T_output.Base
connect VCC to R_led.in
connect R_led.out to LED.anode
connect LED.cathode to T_output.Collector
connect T_output.Emitter to GND
```

**Step 4: Route on Grid**

The Synthesizer places these components on the [Z, X, Y] grid and routes copper traces between them.

## Example 2: Complex Logic

### User Code

```hw
rule "Safety Controller":
    if TempSensor.temperature > 80 C and System.armed:
        Alarm state is ON
        Motor state is OFF
    else:
        Alarm state is OFF
```

### Compilation Process

**Step 1: Parse Conditions**
- Condition A: `TempSensor.temperature > 80 C`
- Condition B: `System.armed`
- Logical Operator: `and`

**Step 2: Generate Logic Circuit**

```hw
# Comparator for temperature
add Comparator named Comp_temp
connect TempSensor.output to Comp_temp.input
# Comp_temp.output = HIGH if temp > 80C

# AND gate for combined logic
add AND_Gate named Logic_and
connect Comp_temp.output to Logic_and.InputA
connect System.armed_signal to Logic_and.InputB

# Output drivers
add Transistor_NPN named T_alarm
add NOT_Gate named Inv_motor
add Transistor_NPN named T_motor

connect Logic_and.Output to T_alarm.Base
connect Logic_and.Output to Inv_motor.Input
connect Inv_motor.Output to T_motor.Base
```

**Logic Flow**:
```
Temp > 80C AND Armed = TRUE:
  → AND gate output = HIGH
  → T_alarm turns ON (Alarm = ON)
  → Inv_motor inverts to LOW
  → T_motor turns OFF (Motor = OFF)

Temp > 80C AND Armed = FALSE:
  → AND gate output = LOW
  → T_alarm turns OFF (Alarm = OFF)
  → Motor state unchanged
```

## Operator Compilation

### Comparison Operators

```hw
<   # Less than → Comparator with inverted inputs
>   # Greater than → Comparator with normal inputs
<=  # Less than or equal → Comparator + OR with equality
>=  # Greater than or equal → Comparator + OR with equality
==  # Equal → XOR + NOT (equality detector)
!=  # Not equal → XOR (difference detector)
```

### Logical Operators

```hw
and  # AND gate (Level 4)
or   # OR gate (Level 4)
not  # NOT gate (Level 4)
```

## State Assignment

### Syntax

```hw
<component> state is <value>
```

### Compilation

**For Digital Outputs**:
```hw
LED state is ON
# Compiles to:
# Set LED control transistor Base = HIGH (5V)

LED state is OFF
# Compiles to:
# Set LED control transistor Base = LOW (0V)
```

**For Analog Outputs**:
```hw
Motor.speed is 75%
# Compiles to:
# PWM circuit with 75% duty cycle
# Or voltage divider outputting 3.75V (75% of 5V)
```

## How the Synthesizer Validates Rules

### Engine A Validation Process

When `hw verify` runs on a rule:

1. **Parse Rule Syntax**: Extract conditions, operators, actions
2. **Generate Circuit**: Create transistor/gate arrangement
3. **Place on Grid**: Assign [Z, X, Y] coordinates
4. **Route Connections**: Calculate copper trace paths
5. **Electrical Analysis**:
   - Calculate voltages at each node (Kirchhoff's Laws)
   - Calculate currents through each component (Ohm's Law)
   - Calculate power dissipation (Joule's Law)
   - Verify transistor thresholds (Level 3)
6. **Thermal Analysis**:
   - Calculate temperature rise in traces
   - Verify components within thermal limits
7. **Logic Verification**:
   - Simulate all input combinations
   - Verify truth table matches intended logic

**Example Error**:
```
❌ Error at Line 34: Logic Rule Unachievable
  Rule: "Safety Controller"
  Condition: TempSensor.temperature > 80 C
  
  Problem: TempSensor outputs 0-3.3V
           Comparator threshold requires 4.0V for 80C
           Maximum sensor output insufficient
  
  Suggestion: Use voltage amplifier or adjust threshold
```

```
           ↓

```
