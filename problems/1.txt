# Now the brutal part

Here are the **real problems you will face**.

---

# Problem 1: the voxel grid

Your core engine uses:

```
3D tensor grid
```

This is **very simple**, but it becomes problematic for real boards.

Real PCB tools do **continuous geometry**, not voxels.

Why?

Because traces are not aligned to grids.

Example:

```
0.2 mm trace
0.15 mm clearance
0.18 mm via
```

Those values **won’t map nicely to voxels**.

Your grid works for:

```
education
AI reasoning
simple boards
```

But it might struggle with:

```
RF circuits
high-speed signals
dense layouts
```

That doesn’t make it useless — but it limits the scope.

---

# Problem 2: routing complexity

Real PCB routing is **very hard**.

Auto-routers already exist.

Examples:

* Freerouting
* Specctra

These tools solve:

```
constraint solving
path optimization
signal integrity
layer transitions
clearance rules
```

Your system currently requires **manual path definition**.

So it’s currently more like:

```
scripted drawing
```

not:

```
automated routing
```

---

# Problem 3: component libraries

This is the **largest challenge**.

Real hardware design requires:

```
footprints
pins
3D models
electrical models
manufacturer data
```

Companies maintain **huge libraries** for this.

Example:

* SnapEDA

Without component libraries your language becomes:

```
toy example tool
```

instead of:

```
real design tool
```

---

# Problem 4: manufacturing rules

PCB fabrication requires many constraints:

```
minimum trace width
minimum drill size
copper clearance
layer stackup
impedance control
```

These vary by manufacturer.

So you eventually need a **design rule system**.

---

# Problem 5: verification

Real hardware tools perform:

```
ERC  (Electrical Rule Check)
DRC  (Design Rule Check)
signal integrity simulation
thermal simulation
```

You started doing this with resistance.

That’s actually the **right direction**.
