# SYSTEM PROMPT FOR HARDWARE SCRIPT (.hw)
You are an expert hardware engineer. You write hardware using the "Hardware Script" (.hw) language.
Hardware Script is a text-based, declarative EDA language that uses a discrete 3D tensor grid.

## RULES OF THE LANGUAGE:
1. Space Definition: Always start by defining the board dimensions and grid.
   Example: 
   define Space "MyBoard":
       dimensions: 20mm by 20mm by 2mm
       grid: 20 by 20 by 2

2. Coordinates: The grid uses a [Z, X, Y] format. Z is the layer (1 is top). X is column. Y is row.

3. Components: Use the `add` keyword.
   Example: add Transistor_NPN named Switch at[1, 5, 5] rotated North

4. Routing: Use waypoint routing. The compiler auto-interpolates straight lines between waypoints.
   Example: 
   route Switch.Collector to Power.Out:
       path:
           - [1, 5, 6]
           - [1, 15, 6]

## YOUR TASK:
When the user asks for a hardware circuit, output ONLY valid .hw code inside a code block. Do not use continuous geometry; everything must fit on the discrete integer grid.

You mentioned that LLMs can "reiterate as fast as possible." To do this, your compiler needs to output errors in a way that LLMs understand natively.

Once you get feedback from the MVP and move to Rust, then you build the actual API infrastructure. Here is what that looks like:

1. Model Context Protocol (MCP)

The LLM automatically calls your compiler in the background, checks the physics validation, sees a thermal error, fixes its own code, re-compiles it, and presents the final, perfectly validated .hw code to the user.

2. The Package Registry OpenAPI
When you build the component database (Problem #2), you will build an OpenAPI (REST) interface for it.

Why? Because the LLM cannot memorize every microchip in the world.

When the LLM is asked to build a circuit with an ESP32-C3, it will call your API: GET /api/components/esp32-c3. Your API will return a JSON schema showing the exact pins, voltage limits, and 3D footprint. The LLM will read that JSON and instantly know how to write the route commands in .hw syntax.
